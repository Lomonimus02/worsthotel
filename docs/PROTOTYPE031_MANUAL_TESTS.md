# Ручной плейтест 0.3.1 — обслуживание гостей

**Статус всех пунктов: НЕ ПРОЙДЕНО ЧЕЛОВЕКОМ.** Это инструкция для будущего плейтеста по [пунктам 47–51 задания](GUEST_SERVICE_REQUEST.txt), с отдельной проверкой двух компьютеров. Модельные тесты, автоматический ввод EXE и просмотр снимков не заменяют эти проверки. Их результаты находятся в [SERVICE_ACCEPTANCE.md](SERVICE_ACCEPTANCE.md) и [VERIFICATION.md](VERIFICATION.md).

Записывайте версию/дату сборки, режим, способ управления, имя и номер гостя, время отеля, действия, результат и непонятные моменты. Для сравнения решений используйте отдельные новые сессии с одинаковым планом; не выдавайте изменённую настройками сцену за естественный день. Основное управление и места предметов: [GUEST_SERVICES.md](GUEST_SERVICES.md).

## Подготовка через F2 — только локальные диагностические ветки

F2 ставит локальную игру на паузу; закройте панель, чтобы гости действительно шли и выполняли действия. Сначала заселите гостя обычным физическим ключом и дождитесь его входа в комнату. Для каждой новой ветки звонка или повторной просьбы берите новую сессию/гостя: одна и та же услуга не должна повторяться бесконечно во время одного проживания.

| Нужно подготовить | Реальные кнопки/поля F2 |
| --- | --- |
| Выбрать объект | `‹ Room` / `Room ›` и отдельно `‹ Guest` / `Guest ›`; проверьте совпадение нужной комнаты и гостя. |
| Лёгкий холод и просьбу | `Set mild cold for selected guest`, затем `Extra blanket`. |
| Температуру/радиатор | `Room temperature` → `Set temperature`; `Radiator (0–3)` → `Set radiator`. |
| Запас одеял | `Blanket stock (0–6)` → `Set shelf stock`; переносимые и выданные предметы занимают свои слоты. |
| Другую просьбу | `Luggage storage`, `Late checkout`, `Wake-up call`, `A little more quiet` под выбранным гостем. Нужна настоящая предпосылка: неподготовленный номер, подходящий остаток проживания или слышимый источник. |
| Дождаться времени обещания | `Advance to next wake-up promise due`; для отдельной проверки опоздания — `Advance seconds` → `Advance simulation`. Это перемотка времени, не физического маршрута. |
| Удержать диагностическую активность | `Force Rest`, `Force Sleep`, `Force Quiet TV`, `Force TV / music`; после закрытия панели дайте гостю дойти до места. Не применяйте их в проверке естественного дня. |
| Проверить лампу | `Break selected room lamp`, затем физическая замена из `REPLACEMENT BULBS`. |
| Проверить данные | `SERVICE MEMORY`, записи `SERVICE` / `PROMISE`, температура/воспринимаемая температура, реальные потребители и `requested` / `delivered`. |

В F2 также есть `Set override`, `DEBUG trip A/B` и сброс автомата. **Для проверки двух настоящих обогревателей они не нужны:** снимите прежний override через `Clear A/B override / use actual consumers`. Аналогично `Reset demand override` возвращает реальную нагрузку бойлера. В LAN F2 отключена.

## 47. Одеяло или обогреватель

- [ ] В начале смены заселить гостя в **104**, записать температуру и потребителей линии B. Через F2 создать лёгкий холод и `Extra blanket`, затем закрыть F2 и согласиться помочь на доске/в разговоре.
- [ ] Взять одеяло с `CLEAN BLANKETS` через F, физически донести; у занятой двери положить предмет, постучать, получить разрешение, поднять тот же предмет и передать через E на `EXTRA BLANKET` у кровати.
- [ ] Убедиться: одно одеяло убыло с полки, оно видно на кровати, просьба выполнена и личный комфорт улучшился. Электрическая нагрузка не выросла; термометр не получил прибавку от одеяла. Обычное изменение температуры со временем допустимо.
- [ ] Сделать холод устойчиво сильным: явно записанный setup `Set radiator` = 0, `Set temperature` = 5 °C. Дать гостю реально находиться в номере и наблюдать накопление недовольства. Уже выданное одеяло должно оказаться недостаточным; серьёзная температурная жалоба должна иметь реальную причину, а не дубликаты просьб об одеяле.
- [ ] Выбрать решение: настоящий включённый обогреватель, радиатор при работающем бойлере, ремонт неисправного бойлера, переселение с правильным ключом либо компенсация. Проверить фактическую реакцию температуры, источника тепла и гостя. Компенсация даёт передышку, но не греет комнату.
- [ ] В отдельной сопоставимой ветке применить обогреватель вместо одеяла: комната постепенно теплеет, а у линии появляется его нагрузка. Записать, почему выбран именно этот способ и была ли цена решения понятна без F2.

## 48. Поздний выезд и настоящее время на подготовку

- [ ] У заселённого гостя записать исходное время выезда. Дождаться `Late checkout` либо явно создать эту диагностическую просьбу через F2, если до конца проживания ещё есть подходящее окно.
- [ ] Прочитать новое абсолютное время, принять и проверить `LATE CHECKOUT` на доске. После исходного срока гость всё ещё занимает номер; нельзя забрать его ключ или начать смену грязного белья раньше реального ухода.
- [ ] Дождаться настоящего выхода, затем лично отнести грязное бельё, принести чистое и заправить кровать. Записать фактически потерянное время подготовки и другие задачи, которыми пришлось пожертвовать.
- [ ] Для давления следующего заселения использовать **обычную заявку следующего дня в этот же номер**. В 0.3.1 одно проживание занимает одну ночь; второй перекрывающейся брони внутри той же смены нет. Продление ограничено концом текущей смены, а выход и грязное бельё проходят через границу дня обычными механиками.
- [ ] Сравнить принятие и отказ в двух сессиях с одинаковым планом следующего дня и тем же порядком работы. Если новый гость пришёл до подготовки, он реально ждёт и не получает грязный/ещё занятый номер. Если времени хватило, записать отсутствие ожидания: не создавать искусственную задержку или «вторую бронь» ради нужного результата.

## 49. Обещанный звонок

Часы показывают время от начала смены, например `4:20`, а не реальные 06:30. Используйте предложенное время; оно должно попадать в текущее проживание. Для каждого исхода нужна отдельная просьба.

| Ветка | Действие человека и ожидаемый результат |
| --- | --- |
| [ ] Вовремя | Принять `Wake-up call`, сверить абсолютное время на UPCOMING. У настоящего телефона reception выбрать комнату и дождаться 1,2 секунды звонка. В текущих настройках своевременное окно — от 8 секунд до срока до 8 секунд после. Обещание выполнено один раз, память показывает одно kept. |
| [ ] Немного поздно | Позвонить примерно через 10–15 секунд после срока, когда гость в номере. До предела 25 секунд звонок ещё завершает то же обещание, с небольшим последствием за опоздание. |
| [ ] Забыть | Не звонить дольше 25 секунд после срока. Получить один `Missed` / broken и умеренное последствие в памяти/отзыве, без повторяющихся штрафов за один звонок. |
| [ ] Прервать разговор | Начать звонок и быстро нажать Backspace / B до завершения. Обещание остаётся невыполненным и не завершается позже само; снова открыть физический телефон и успеть повторить. |
| [ ] Отменить обещание заранее | До срока выбрать на доске `Cancel promised call`: обещание отменено, а не выполнено. Отмена может иметь небольшой штраф за отказ. |
| [ ] Отменить после срока | Выбрать `Cancel overdue call · counts as missed`: зафиксирован пропущенный звонок, а не успешное обслуживание. |

Проверьте, что доска только напоминает: удалённо выполнить звонок с неё нельзя. Если гость ушёл из отеля, телефон не должен считать его ответившим. Для отдельной проверки сна можно использовать `Force Sleep`: завершённый звонок переводит находящегося в номере спящего гостя к отдыху.

## 50. Два обогревателя и повторное отключение

- [ ] Заселить одного гостя в **104**, оставить 105–106 свободными. Физически принести оба существующих обогревателя из служебной зоны в 104, положить и включить. Не создавать нагрузку через F2.
- [ ] Открыть электрощит и проверить линию **B (104–106)**: два реальных обогревателя по 2,0 плюс базовые 0,85 занятого номера превышают вместимость 4,0. Возможная активность гостя может добавить нагрузку; запишите реальные значения.
- [ ] Дождаться предупреждения и отключения. Обогреватели остаются включёнными, но без питания перестают греть; запрос нагрузки сохраняется, фактическая подача падает.
- [ ] Сбросить настоящий автомат, ничего не выключая. Дождаться повторного отключения — один сброс не устраняет причину.
- [ ] Выключить один обогреватель либо убрать его с этой линии, затем снова сбросить автомат. Проверить, что запрошенная нагрузка ниже вместимости и питание остаётся включённым дольше периода срабатывания (по умолчанию 18 секунд).
- [ ] Записать, удалось ли понять виновника по видимым потребителям без панели разработчика и угадывания.

## 51. Естественный тихий день

- [ ] Начать новую SOLO-сессию без F2, принудительных просьб, поломок, температур и перемотки модели. Провести смену, в которой бойлер сам не сломался; обычный WAIT разрешён, когда делать действительно нечего.
- [ ] Записать прибытия, подготовку, наблюдаемую жизнь гостей, принятые решения и реальные просьбы. Ориентир — несколько услуг за день, но отсутствие конкретного типа или отсутствие просьб у отдельного гостя допустимо. Нельзя обеспечивать разнообразие кнопкой Force.
- [ ] Отметить периоды полезной работы, спокойного наблюдения и пустого ожидания в реальных секундах. Ориентир 20–40 секунд между осмысленными занятиями — вопрос оценки темпа, не обязательный таймер новых событий.
- [ ] Ответить: было ли чем заняться без аварии; оставался ли выбор порядка; помогал ли UPCOMING готовиться; были ли причины понятны; превращались ли просьбы в непрерывный бег по уведомлениям? Повторить короткую часть с другим устройством ввода.

## Настоящая LAN-игра на двух компьютерах

- [ ] Распаковать одинаковую сборку на двух отдельных ПК одной сети. Один выбирает HOST GAME, другой JOIN GAME по IPv4 хоста (не `127.0.0.1`); порт UDP 7777. Записать сеть, ПК и способ ввода каждого игрока.
- [ ] Совместно пройти обычную смену без F2. Разделить reception и подготовку, затем поменяться задачами: у игроков нет закреплённых классов.
- [ ] Проверить общие просьбы, обещания и запас. Один принимает просьбу; другой видит тот же статус и физически доставляет предмет. Одновременное действие не дублирует одеяло, чемодан, ключ или завершение звонка.
- [ ] Передать обслуживание между игроками: положить предмет и поднять его другим сотрудником; сменить владельца следующего действия. Если естественной просьбы за сессию не было, соответствующую проверку оставить «не наблюдалось».
- [ ] Проверить реальную доставку одеяла, хранение багажа при ожидании комнаты, телефон при обещании, поздний выезд, лампу при её поломке и состояние обоих обогревателей/линий на обоих ПК. Отсутствующие естественные условия не подменять утверждением об успехе.
- [ ] При безопасно положенных предметах проверить отключение клиента и показ понятного состояния соединения; отдельно при переносе проверить освобождение предмета без копии и зависшего владельца. Записать фактическое поведение и доступный путь продолжения; перенос хоста и интернет-matchmaking не заявлены.

Для каждого пункта оставьте **PASS / FAIL / НЕ НАБЛЮДАЛОСЬ**, краткий факт и при необходимости снимок/Player.log. Не закрывайте человеческую приёмку результатом двух EXE на одном ПК. Старый чек-лист [Prototype 0.3](PROTOTYPE03_MANUAL_TESTS.md) остаётся отдельной регрессией поведения гостей.
