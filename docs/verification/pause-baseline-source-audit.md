## What “pause” currently means

| State | Current behavior and source |
| --- | --- |
| SOLO Alt+Tab out | SOLO is `LanRole.Offline` (`Core/LocalCoopBootstrap.Solo.cs:14–28`). `OnApplicationFocus(false)` sets `hasFocus=false`, then `RefreshPause()` chooses `manuallyPaused || WaitingForDevices || !hasFocus`. Entering pause calls every existing player's `CancelInteraction()`, then sets `Time.timeScale=0` (`Core/LocalCoopBootstrap.cs:253–280`). |
| SOLO return to window | `OnApplicationFocus(true)` runs the same calculation. If no manual/device pause remains, it immediately changes `IsPaused=false` and `Time.timeScale=1`. It does not wait for an Esc press. Cursor lock/visibility are recalculated in the following bootstrap Update (`Core/LocalCoopBootstrap.cs:241–250,274–280`). |
| Esc / Start | In the normal SOLO build, `LanSession.ReadMenuInput` toggles the session menu and calls `SetPaused(MenuOpen)` (`Networking/LanSession.Menu.cs:31–51`). The direct bootstrap Esc toggle excludes normal SOLO with a `LanSession` (`Core/LocalCoopBootstrap.cs:244–245`). Therefore menu pause sets a manual flag which survives focus regain; focus pause alone does not. |
| F2 | Local-only developer panel remembers the previous pause, sets manual pause, then restores it on closing. Explicit developer step/advance commands can still change the model while its panel is paused (`UI/DeveloperPanel.cs:49–66`, `Core/GameSession.Service.cs:138–157`). This is a diagnostic exception, not ordinary Alt+Tab behavior. |
| LAN host focus loss | Focus/device loss does **not** choose hotel pause for a network role. It cancels this computer's physical interaction and clears local intentions; the peer and host simulation may continue (`Core/LocalCoopBootstrap.cs:255–280`, `Networking/LanWorldInput.cs:52–59,149–180`). Host Esc/menu pause does stop host gameplay and is replicated as `hostPaused`. |
| LAN client focus/menu pause | Client focus loss suppresses local intentions. Its menu or a host-paused/no-snapshot flag pauses the client presentation clock, without freezing the host. Host snapshots continue to be applied; there is no client hotel tick authority (`Networking/LanWorldInput.cs:111–132`, `Core/LocalCoopBootstrap.cs:257–265`, `Core/GameSession.Service.cs:38`). A local client pause is not a global hotel pause. |

## Focus/input/graphics path relevant to Alt+Tab

- Build settings use Unity `6000.3.2f1`, Input System `1.17.0`, URP `17.3.0` (`ProjectSettings/ProjectVersion.txt:1`, `Packages/manifest.json:5–6`). `runInBackground=1`, `muteOtherAudioSources=0`, `useFlipModelSwapchain=1`, `fullscreenMode=3` are serialized in `ProjectSettings/ProjectSettings.asset:86–111`. `LanSession.Awake` also sets `Application.runInBackground=true` even when its menu starts SOLO (`Networking/LanSession.cs:59–64`). The project therefore requests a live background player loop; actual operating-system/graphics-driver behavior still requires runtime evidence.
- There is one project `OnApplicationFocus` handler and no project `OnApplicationPause` handler found in the gameplay scripts. It does not reset render targets, swap chains, cameras or audio devices. Camera creation and listener selection occur during player construction/authority configuration, not in that focus callback (`Core/FirstPersonController.cs:36–86`). No custom focus-specific graphics recovery path was found. This does not establish whether Unity/native graphics or audio was involved in the reported crash.
- Input System has its own focus handler. The package default is `ResetAndDisableNonBackgroundDevices` and Dynamic Update (`Library/PackageCache/com.unity.inputsystem@02433b2481ab/InputSystem/InputSettings.cs:763,769`); `EditorBuildSettings.asset` has no configured input-settings object. The archived build-4 report independently records that exact policy (`Logs/services-player-release.txt:2`). On loss, the package temporarily disables and soft-resets devices which cannot run in the background; on gain, it reenables/synchronizes them and discards out-of-focus events (`…/InputSystem/InputManager.cs:2964–3065`). Native device behavior and callback ordering have not been measured here.
- The project's `onDeviceChange` callback merely sets `devicesDirty`; the next Update reassigns controls and cancels interactions. Assignment filters enabled gamepads, preserves the chosen ID when available, otherwise selects a pad or keyboard/mouse, and `Bind` clears the local frame (`Core/LocalCoopBootstrap.cs:37–60,168–187,241–242`). SOLO's `DeviceReady` is based on assigned references, not a separate OS focus lease. These callbacks form part of the return path; none is proven faulty by this audit.
- Existing EXE verification drivers register private background-capable synthetic pads and explicitly send a focus-true message (`Core/DevelopmentVerification.cs:55–59,169`; LAN driver uses the same technique). Those earlier passing runs do **not** reproduce a real Windows Alt+Tab/input-device transition.

## Time and subsystem behavior

| Subsystem | Pause semantics in the inspected source |
| --- | --- |
| Hotel clock / accumulator | The actual runtime class is `HotelGameClock`, not a separate `SimulationClock` class (`Simulation/HotelGameClock.cs:12–31`). `GameSession.Update` returns before adding `Time.deltaTime * Clock.Speed` when paused; it retains the fractional accumulator. Unpaused fixed steps drive Planning preparation or Service ticks (`Core/GameSession.Service.cs:17,36–64`). No subtraction of wall-clock timestamps or stored real-time pause gap feeds this accumulator. A resume burst is **not observed or disproven** by source inspection. |
| Planning / other phases | Planning runs only `AdvancePreparation`, housekeeping and hotel-clock advance; ordinary guest service simulation runs in Service (`Simulation/HotelSimulation.Housekeeping.cs:20–28`). Settlement/Maintenance/Results do not tick the hotel through GameSession.Update. Existing visual guest departures can still move in these phases with `Time.deltaTime`, until paused (`Guests/GuestPresentation.cs:265–273`). |
| Guest AI / perception / situations | Service Tick advances guest schedules, waiting/checkout, electricity/noise/boiler/temperature, perceived needs, incidents, services, satisfaction and finally the clock (`Simulation/HotelSimulation.cs:153–190`, `HotelSimulation.Guests.cs:129–163`). These model updates stop with the caller. Schedule entries are a finite 24-entry array per guest, not realtime coroutine timers (`GuestScheduleSystem.cs:60–80`). No autonomous NavMesh agent is used: guests follow authored routes (`Guests/GuestPresentation.cs:259–307`). |
| Physical guest navigation | `LateUpdate` may bind/refresh presentation before the pause check, but returns before travel/staging while paused. Movement budget comes from actual hotel-time increments, not elapsed wall time (`Guests/GuestPresentation.cs:259–299`); staging blends use scaled delta time (`GuestPresentation.Staging.cs:46–53`). The retained budget has not been measured across a long focus loss. |
| ServiceCases / promises | Service generation and status checks run from `GuestServiceSystem.Tick`; promises compare hotel `now` with due/grace times (`Simulation/GuestServiceSystem.cs:95–115`, `GuestServiceSystem.Commands.cs:58–85`). Paused hotel time alone cannot make a wake promise late. Cases/promises/items are model lists (`GuestServiceSystem.cs:20–22`), not pending asynchronous callbacks. |
| Unity physics / hands | `timeScale=0` stops ordinary scaled fixed stepping. No project manual `Physics.Simulate`/alternate simulation-mode driver was found. Doors and grab hand updates use FixedUpdate/fixedDeltaTime (`Environment/DoorInteractable.cs:114–130`, `Interaction/PlayerInteractor.cs:125–143`). Entering pause explicitly ends held interactions and releases the carried body/joint; carrying is **cancelled**, not retained for resume (`PlayerInteractor.cs:146–171`). Player locomotion also returns while paused (`Core/FirstPersonController.cs:112–120`). |
| Boiler repair | Pause cancels physical holds, the SOLO valve catch and an active failed-boiler repair attempt; this is an intentional existing gameplay change on pause (`Infrastructure/RepairSequenceController.cs:34–46`). It is not frozen resumable work. |
| Audio / feedback | Hotel mechanical cues/footsteps/reception sounds, room activity channels, panel hum/effects and heater fan explicitly call `AudioSource.Pause/UnPause` on pause edges (`Environment/HotelFeedback.cs:96–107`, `Guests/LivingGuestAudio.cs:80–92`, `Environment/ElectricalPanelPresentation.cs:79–84`, `Environment/PortableHeaterAudio.cs:34–40`). No global `AudioListener.pause` assignment was found. UI click source is excluded from the hotel's paused-source list (`HotelFeedback.cs:38–56`). This is source coverage, not an audible/native-device test. |
| UI and realtime exceptions | Management UI Update returns while paused but its page remains renderable (`UI/ManagementUI.cs:55–78,110`). A phone call's 1.2-second animation deadline and the 60-second phone grant use `Time.unscaledTime`: after a pause, its next Update can attempt completion immediately, and a long-expired grant can reject it (`UI/ManagementUI.ServiceBoard.cs:56–78`, `Core/GameSession.GuestServices.cs:99–123`). Conversation grants similarly expire after 30 unscaled seconds (`Core/GameSession.Conversations.cs:46,63`). These deadlines differ from hotel promise due times. No change is proposed from this observation. |
| WAIT | Votes use unscaled hold duration, but pause/device blockers run first. Stop resets hotel speed to 1 and clears votes, requiring release before another vote. SOLO needs one vote; co-op two (`Core/WaitController.cs:33–68,81–90,104–113`). WAIT accelerates model ticks, not Unity timeScale or fixedDeltaTime. |

## Networking and event lifetime

Host sends model snapshots every 0.2 unscaled seconds and compressed world snapshots every 0.05 even while its hotel is paused, carrying `hostPaused` (`Networking/LanSession.cs:228–250`). Client input lease renewal and receive/apply paths remain active; blocked input becomes an empty intent. Remote input lease is 0.35 unscaled seconds; stale world presentation clears after 0.5 seconds, and the client has 10-second initial / 5-second stale-model timeout checks. UTP disconnect timeout is 4,000 ms (`LanWorldInput.cs:39,111–125,176–180`; `LanWorldReplicator.cs:289–298`; `LanSession.cs:87,217–225`). These are separate from hotel time. This audit did not measure queues, transport pressure or timeout behavior while unfocused.

No runtime gameplay `StartCoroutine`, `WaitForSeconds`, repeating Invoke or scheduled async queue was found in the inspected custom scripts; the non-diagnostic coroutine found is `LanSession.Start`, which waits for composition via `yield return null` (`LanSession.cs:67–79`). Model events are synchronous delegates; the hotel event signal stores one latest string plus an incrementing revision (`Simulation/HotelSimulation.cs:13–16`). HUD pages project current state rather than a discovered notification queue. This does **not** prove that Unity, Input System, NGO/UTP, rendering or audio allocate nothing during pause; growth must be measured.

Existing `SoloPlayModeTests.cs:68–71` directly invokes false/true focus callbacks without a real wait or native focus transition. WAIT/audio/repair tests cover short manual pause effects. They cannot establish long Alt+Tab stability or classify a native crash. The required next evidence is an actual focus-out → elapsed interval → focus-in capture with state/accumulator/tick counts, input-device changes, low-frequency memory/queue measurements and Player.log/crash artifacts. Record whether failure occurs before focus gain, on the first resumed frame, or later. **No root cause or fix is established here.**
