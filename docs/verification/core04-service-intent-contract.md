# Phase 4 implementation contract

Agreed direction, pending the phase 3 gate. Implement only after root explicitly authorizes phase 4. The two design audits supply rationale; this file fixes ownership and the narrower player-facing policy.

- Existing factual temperature, power, lamp and noise incidents are Remote. Presence outside the assigned room is not evidence of recovery. The guest may continue life; an actual return and fresh perception govern resolution.
- An `ExtraBlanket` service case becomes an explicit request to leave a blanket (DropOff). Its normal contact/acceptance wording must actually promise the item. The underlying temperature incident remains Remote; a blanket is personal comfort, not a boiler repair. Do not add another compulsory request generator or duplicate problem cards. A guest may abandon an unneeded request without a false delivery reward.
- Communicated late-checkout, wake-up agreement and luggage agreement decisions are Direct until a decision or finite deadline. Accepting a future wake-up call releases the decision wait; the promise persists. Existing proposed room change is Direct until real key exchange, explicit cancellation or timeout. No new random room-change generator is required.
- One small intent record attaches to existing response/case/incident identities, plus the command-originated room-move purpose. Keep one active Direct wait per guest. Schedule queries the same record; closing UI does not end it. No copied UI timers or second simulation clock.
- An exterior blanket point per room accepts the actual carried finite-stock item. Pending receipt preserves exact item/generation/recipient/room and has no early comfort or memory credit. Actual return/availability applies receipt once. Unreceived checkout/relocation parcels become reclaimable actual items; no automatic teleport to a new room or midnight refill.
- Preserve ordinary physical privacy, handoffs, versioned route callbacks, authority and legacy fixture behavior. Continuous mode opts into intent behavior. New generation/contact checks defer during sleep/shower/transfer, imminent outing/checkout and conflicting direct waits.

Proposed ownership for the implementation gate: Agency Life owns intent runtime/data, service scheduling and receipt lifecycle; Agency Interface owns physical drop points, session/UI/LAN command integration and physical tests; Agency Situations owns Remote incident suspension/reassessment and its focused causal tests; root owns model snapshot DTO/validation/retention integration, versions, gates/builds and cross-system tests. Confirm exact runtime API with all agents before simultaneous edits. No agent runs Unity.
