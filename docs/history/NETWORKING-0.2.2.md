# Историческая сводка LAN и SOLO — Prototype 0.2.2

**Реконструированная историческая сводка, не точная копия исходного NETWORKING.md.** При обновлении документации 0.3.0 исторический файл оказался пустым. Этот текст восстановлен по сохранённому [отчёту 0.2.2](VERIFICATION-0.2.2.md) и перечисленным ниже исходным артефактам. Он не подтверждает нынешнюю сборку; текущий протокол и команды описаны в [NETWORKING.md](../NETWORKING.md).

0.2.2 предлагал SOLO / HOST GAME / JOIN GAME, одну камеру на игрока, одного хоста и одного клиента по прямому IPv4. Модель и физический мир рассчитывались хостом; клиент был read-only зеркалом. Сетевой протокол имел **версию 2**. SOLO использовал одного настоящего сотрудника и помощь с временной фиксацией клапана для ремонта котла. Приватность сна и душа, постановка активности до её воздействия, занятые двери и временный выход гостя относились к Guest Presence; расширенные причины и память Guest Agency появились в 0.3.

## Сохранённые результаты 0.2.2

Финальный двухпроцессный запуск **20260926-120535-f938e247** по localhost дал **PASS / Errors=0**, host **29**, client **162** checks. [Host report](../verification/lan/20260926-120535-f938e247/host-report.txt), [client report](../verification/lan/20260926-120535-f938e247/client-report.txt).

- По одной камере и AudioListener на процесс; host actor0 — world authority, client actor1 — зеркало.
- Assign и Commit прошли обычным транспортом; ключ физически поднят, перенесён на **2,38 м**, сброшен и поднят повторно.
- Измеренные ошибки поз сотрудника и ключа — **0,000 / 0,000 м**. При разрыве хост освободил удержание; клиент сохранил read-only и отключённую физику.
- **609** проверок client clock только по snapshot; локальный Tick отклонён.
- Явный выход в главное меню и новая SOLO-сессия дали `SoloAfterLan=True`, `StaffObjects=1`.
- Размеры снимков в том состоянии: model **10948 B**, world **104277 B**. Это не измерение пропускной способности.

Пустой удалённый сотрудник был диагностически поставлен рядом с ключницей; дальнейшие предметные действия выполнялись собственным виртуальным геймпадом клиента через обычный NGO. Диагностических RPC не было, stage-файлы не меняли гостиничное состояние. Это не полный ручной маршрут от точки появления.

В сохранённой приёмке отмечены три просмотренных кадра: [игровая камера](../verification/lan/20260926-120535-f938e247/client-one-camera-play.png), [разрыв](../verification/lan/20260926-120535-f938e247/client-connection-menu.png), [главное меню](../verification/lan/20260926-120535-f938e247/client-host-join-menu.png). Это исторические изображения, не визуальная проверка 0.3.

Финальный SOLO 0.2.2 имел **PASS / Errors=0 / ResetVerified=True**, **198,2 с**, 26 GPU-кандидатов, 3 отчёта, 4/6/6 оплаченных проживаний и 11 модельных действий белья. [Архив отчёта](../../Logs/p022-presence-player.txt), [player log](../../Logs/p022-presence-player.log). Более подробные Scene/EditMode/PlayMode и визуальные результаты сохранены в [VERIFICATION-0.2.2.md](VERIFICATION-0.2.2.md).

Эти проверки не доказывали две физические машины, управление двумя людьми, reconnect, сетевую выдачу ключа гостю, полный ручной оборот белья, ремонт вдвоём, несколько сетевых дней или качество аудио/FPS. Все эти границы относились к 0.2.2; актуальные доказательства и ограничения следует читать в нынешнем [VERIFICATION.md](../VERIFICATION.md).
