# THE WORST HOTEL EVER — Prototype 0.3.1 Guest Service Layer

Кооперативная игра о владельцах старого отеля: шесть комнат, три дня, гости, бойлер, электричество, экономика и физические предметы. Версия 0.3.1 продолжает существующий проект: между обычной жизнью и серьёзными жалобами появились редкие просьбы об обслуживании. Требования: [GUEST_SERVICE_REQUEST.txt](docs/GUEST_SERVICE_REQUEST.txt); новые действия и настройки: [GUEST_SERVICES.md](docs/GUEST_SERVICES.md).

На reception есть доска NOW / UPCOMING и телефон для обещанных звонков. Одеяла берут с полки CLEAN BLANKETS, лампочки — с maintenance shelf; багаж относят на площадку у стойки. Кнопки E / Q меняют радиатор 0–3: больше тепла увеличивает нагрузку на бойлер. Поздний выезд даёт небольшой бонус гостю, но оставляет меньше времени на бельё и подготовку номера. Электрощит показывает реальные потребители; сброс без снятия перегрузки приводит к повторному отключению.

Шум создают реальные телевизоры, телефонные разговоры и душ. Гость испытывает условия только находясь в своём номере. Одна причина остаётся одной ситуацией, которая может усилиться, восстановиться после улучшения условий и повториться с меньшим терпением. Компенсация даёт передышку, но оставляет причину активной. Переселение меняет фактическое воздействие; просьба вести себя тише уменьшает источник.

Гости распаковываются, работают за столом, отдыхают, смотрят телевизор, звонят, принимают душ, спят, выходят из отеля и возвращаются. Расписание зависит от характера и воспроизводимого случайного выбора. Большинство этих действий не создаёт уведомлений.

[Запустить Windows-сборку](Builds/Windows-0.3.1/TheWorstHotelEver.exe) · [Полный ZIP для друга](Builds/TheWorstHotelEver-0.3.1-Windows.zip). Распакуйте архив целиком: EXE должен оставаться вместе с соседними DLL и папками. Внутри есть `README-RU.txt`; Unity Editor игроку не нужен. Актуальный статус сборки и проверок: [VERIFICATION.md](docs/VERIFICATION.md).

## Играть

Выберите **SOLO** для одного сотрудника с одной полноэкранной камерой. Для двух компьютеров одной сети: **HOST GAME**, затем **JOIN GAME** с IPv4 хоста. Нужны одинаковые сборки; порт по умолчанию UDP 7777. Два экземпляра на одном компьютере используют `127.0.0.1`. [Подробности LAN](docs/NETWORKING.md).

| Действие | Клавиатура/мышь | Геймпад |
| --- | --- | --- |
| Ходить / смотреть | WASD / мышь | Левый / правый стик |
| Взаимодействовать / постучать | E | A / Cross |
| Дополнительное действие | Q | X / Square |
| Взять / отпустить предмет | F | RB / R1 |
| WAIT | Удерживать T | Удерживать Y / Triangle |
| Книга и разговор: выбор / подтвердить / назад | Стрелки / Enter / Backspace | D-pad / A / B |
| Меню сессии / пауза | Esc | Start |

Первое E у занятой двери — стук, второе после ответа — компактный выбор действий. Выберите просьбу о тишине, компенсацию, переселение или разрешение войти, когда это уместно. Открытие разговора само по себе не выбирает ответ.

Ключи берут с номерной стойки и передают гостю одним нажатием. После выезда хозяева относят грязное бельё в корзину, приносят чистое с полки и заправляют кровать за 1,5 секунды. Бесплатной горничной нет. Переносной обогреватель нужно поставить в комнате, отпустить и включить; его нагрузка может перегрузить линию.

В SOLO удерживайте клапан бойлера в зелёной зоне ещё 2 реальные секунды до **SOLO CATCH**. Затем есть 18 активных секунд на панель → рубильник → фиксаторы A/B → RESTART. В кооперативе клапан непрерывно держит партнёр.

[Полное русское руководство](docs/HOW_TO_PLAY.ru.md). Интерфейс прототипа на английском; сохранений между запусками нет. F2 открывает локальную отладку причин, памяти, активности и распространения шума; в LAN панель отключена.

## Исходники и проверка

Unity **6000.3.2f1**. На этой машине Editor находится в `D:\UnityEditors\6000.3.2f1\Editor\Unity.exe`. Откройте корень проекта и сцену `Assets/_WorstHotel/Scenes/PrototypeHotel.unity`. Команда `Tools → Worst Hotel → Build Prototype Scene` пересоздаёт сгенерированную сцену; ручные изменения сцены предварительно сохраните в копии.

При закрытом Editor этого проекта:

```powershell
./tools/Unity.ps1 -Task Scene
./tools/Unity.ps1 -Task Test
./tools/Unity.ps1 -Task PlayTest
./tools/Unity.ps1 -Task Build -BuildDirectory Builds/Windows-0.3.1
./tools/VerifyPlayer.ps1 -BuildDirectory Builds/Windows-0.3.1 -Solo -ServiceFixtures -OutputPath docs/screenshots/services-solo
./tools/VerifyLAN.ps1 -BuildDirectory Builds/Windows-0.3.1 -Capture
./tools/VerifyLAN.ps1 -BuildDirectory Builds/Windows-0.3.1 -ServiceFixtures -Capture
```

`VerifyPlayer -ServiceFixtures` запускает реальный Windows player и два отдельных диагностических отеля: физические одеяло, радиатор, замена лампочки, багаж, звонок с отменой и повтором, поздний выезд. Исходные просьбы, лёгкий холод, перегоревшая лампа и грязная комната задаются явно; случайные просьбы отключены только в копии настроек сценария. Начальная расстановка сотрудника и передача ключей обозначены как MODEL/диагностические операции; перенос предметов, выбор ответов и маршруты гостей выполняются игрой через настоящий ввод и физику. Затем восстанавливаются рабочие настройки, отель сбрасывается и отдельно проходят три дня с естественными расписаниями. Ключи и бельё в этом длинном проходе обслуживаются обозначенными MODEL-командами; физический перенос имеет отдельные PlayMode-проверки. Снимки показывают настоящую камеру и IMGUI; результаты запуска и визуального осмотра фиксируются отдельно.

`VerifyLAN` использует два самостоятельных EXE и настоящий NGO transport по localhost. Это не проверка двух физических компьютеров. Человеческая оценка темпа, понятности причин, аудиомикса и работы в удалённой сети остаётся отдельным плейтестом.
