# THE WORST HOTEL EVER — Prototype 0.3.2 Natural Service

Кооперативная игра о владельцах старого отеля: шесть комнат, три дня, гости, бойлер, электричество, экономика и физические предметы. В 0.3.2 гость сначала замечает неудобство, терпит его или пробует помочь себе, затем при необходимости связывается с сотрудниками. Полное обращение появляется после разговора. Требования: [NATURAL_SERVICE_REQUEST.txt](docs/NATURAL_SERVICE_REQUEST.txt); действия и настройки: [GUEST_SERVICES.md](docs/GUEST_SERVICES.md).

Natural Service 0.3.2 реализован и собран для Windows. Проверены модель, игровые взаимодействия, услуги и три дня в SOLO, два сетевых сценария в настоящих EXE по localhost. Точные результаты и ограничения: [VERIFICATION.md](docs/VERIFICATION.md). Расследование зависания после Alt+Tab **отложено по просьбе пользователя**: причина не установлена, исправление и успешная длительная проверка паузы не заявляются. Сохранённые сведения: [PAUSE_CRASH_INVESTIGATION.md](docs/PAUSE_CRASH_INVESTIGATION.md).

Звонящий телефон на reception сообщает только о звонке. Подойдите, нажмите E / A и выберите **Answer reception call** — теперь можно узнать проблему и отдельно решить, помогать ли. Другой гость сам придёт к стойке; с ним можно поговорить через E / A. У занятого номера постучите и после ответа начните разговор вторым нажатием. Доска NOW / UPCOMING хранит уже известные обращения и договорённости. Звонки ограничены по длительности и числу попыток; просьба не гарантируется каждому гостю.

При лёгком холоде гость может дойти до своего радиатора и увеличить настоящую настройку: это повышает нагрузку на бойлер. Одеяло с полки CLEAN BLANKETS улучшает личный комфорт, но закрытие проблемы зависит от устойчивого улучшения условий. Игрок выбирает между одеялом, отоплением, обогревателем, ремонтом, переселением и другими доступными ответами. Лампочки берут с maintenance shelf, багаж относят к стойке. Поздний выезд оставляет меньше времени на подготовку номера. Электрощит показывает реальные потребители; сброс без снятия перегрузки приводит к повторному отключению.

Шум создают реальные телевизоры, телефонные разговоры и душ. Гость испытывает условия только находясь в своём номере. Одна причина остаётся одной ситуацией, которая может усилиться, восстановиться после улучшения условий и повториться с меньшим терпением. Компенсация даёт передышку, но оставляет причину активной. Переселение меняет фактическое воздействие; просьба вести себя тише уменьшает источник.

Гости распаковываются, работают за столом, отдыхают, смотрят телевизор, звонят, принимают душ, спят, выходят из отеля и возвращаются. Расписание зависит от характера и воспроизводимого случайного выбора. Большинство этих действий не создаёт уведомлений.

Игра: [Windows 0.3.2](Builds/Windows-0.3.2/TheWorstHotelEver.exe) · [ZIP 0.3.2 для друга](Builds/TheWorstHotelEver-0.3.2-Windows.zip), около 71 МБ. Распакуйте архив целиком: EXE должен оставаться вместе с соседними DLL и папками. Unity Editor игроку не нужен. В архиве есть русское руководство; все 280 файлов сверены со сборкой по SHA256. [Проверка упаковки](docs/verification/natural-service-release-package.txt). Предыдущая 0.3.1 сохранена отдельно.

## Играть

Выберите **SOLO** для одного сотрудника с одной полноэкранной камерой. Для двух компьютеров одной сети: **HOST GAME**, затем **JOIN GAME** с IPv4 хоста. Нужны одинаковые сборки; порт по умолчанию UDP 7777. Два экземпляра на одном компьютере используют `127.0.0.1`. [Подробности LAN](docs/NETWORKING.md).

| Действие | Клавиатура/мышь | Геймпад |
| --- | --- | --- |
| Ходить / смотреть | WASD / мышь | Левый / правый стик |
| Взаимодействовать / постучать | E | A / Cross |
| Дополнительное действие | Q | X / Square |
| Взять / отпустить предмет | F | RB / R1 |
| WAIT | Удерживать T | Удерживать Y / Triangle |
| Книга и разговор: выбор / подтвердить / назад | Стрелки / Enter / Backspace | D-pad / A / B |
| Меню сессии / пауза | Esc | Start |

Первое E у занятой двери — стук, второе после ответа — разговор и компактный выбор действий. Гость может рассказать о существующей проблеме. Получение информации не означает согласие помочь, доставку предмета или разрешение войти; каждый ответ выбирается отдельно.

Ключи берут с номерной стойки и передают гостю одним нажатием. После выезда хозяева относят грязное бельё в корзину, приносят чистое с полки и заправляют кровать за 1,5 секунды. Бесплатной горничной нет. Переносной обогреватель нужно поставить в комнате, отпустить и включить; его нагрузка может перегрузить линию.

В SOLO удерживайте клапан бойлера в зелёной зоне ещё 2 реальные секунды до **SOLO CATCH**. Затем есть 18 активных секунд на панель → рубильник → фиксаторы A/B → RESTART. В кооперативе клапан непрерывно держит партнёр.

[Полное русское руководство](docs/HOW_TO_PLAY.ru.md). Интерфейс прототипа на английском; сохранений между запусками нет. F2 открывает локальную отладку причин, памяти, активности и распространения шума; в LAN панель отключена.

## Исходники и проверка

Unity **6000.3.2f1**. На этой машине Editor находится в `D:\UnityEditors\6000.3.2f1\Editor\Unity.exe`. Откройте корень проекта и сцену `Assets/_WorstHotel/Scenes/PrototypeHotel.unity`. Команда `Tools → Worst Hotel → Build Prototype Scene` пересоздаёт сгенерированную сцену; ручные изменения сцены предварительно сохраните в копии.

При закрытом Editor этого проекта:

```powershell
./tools/Unity.ps1 -Task Scene
./tools/Unity.ps1 -Task Test
./tools/Unity.ps1 -Task PlayTest
./tools/Unity.ps1 -Task Build -BuildDirectory Builds/Windows-0.3.2
./tools/VerifyPlayer.ps1 -Solo -ServiceFixtures -BuildDirectory Builds/Windows-0.3.2 -OutputPath docs/screenshots/natural-service-solo
./tools/VerifyLAN.ps1 -BuildDirectory Builds/Windows-0.3.2 -Capture
./tools/VerifyLAN.ps1 -BuildDirectory Builds/Windows-0.3.2 -ServiceFixtures -Capture
```

Новые проверки разделяют модель причин и общения, настоящие маршруты гостя и физический ввод сотрудника. Полный EditMode прошёл 316/316; все 49 разных PlayMode-случаев имеют успешные результаты после исправлений и выборочных повторов, без нового полного запуска 49/49. SOLO завершил услуги, новые контакты, три дня и сброс без ошибок; финальная сборка прошла оба LAN-сценария. После SOLO менялись только сроки ожидания в LAN-диагностике; происхождение бинарников записано в отчёте.

В сценариях явно обозначаются заданная температура, принудительно выбранный канал обращения и передача ключа через модель; они не считаются естественным темпом или физическим переносом ключа. В отдельном проходе трёх дней использовались обычные настройки гостей и инфраструктуры, диагностическая скорость времени и модельные команды ключей/белья. Вызовы, на которые сотрудник не ответил, не становятся известными заданиями.

`VerifyLAN` использует два самостоятельных EXE и настоящий NGO transport по localhost. Это не проверка двух физических компьютеров. Человеческая оценка темпа, понятности причин, аудиомикса и работы в удалённой сети остаётся отдельным плейтестом.
